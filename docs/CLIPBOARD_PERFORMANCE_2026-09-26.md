# inVoice 0.3.1：剪贴板性能与 Rust 评估

下方前半部分记录 0.3.1 实测；0.3.2 已取消 200 条限制，容量策略与大历史实测见文末。

## 实测

2026-09-26，本机 Apple Silicon，Swift `-O`。两个版本依次运行；基线为已发布的
`1130a0981503fd819fdf1b888cb353cf8a27fc43`（0.3.0）。图片使用固定随机种子的
3840 × 2160 合成 RGB 噪声图，PNG 为 24,911,302 字节。搜索使用 200 条中英文长文本。

| 阶段 | 0.3.0 中位数 / P95 | 0.3.1 中位数 / P95 | 样本数 |
| --- | --- | --- | --- |
| PNG 采集准备 | 446.341 / 457.868 ms | 0.049 / 1.033 ms | 7 |
| 提交图片记录的调用线程耗时 | 7.406 / 7.583 ms | 0.003 / 0.017 ms | 15 |
| 搜索并加载 200 条长文本、读取计数 | 1.902 / 2.446 ms | 1.278 / 1.463 ms | 30 |

第一项收益来自跳过 PNG 解码和重编码。第二项是把哈希移到后台，哈希和磁盘写入仍会
消耗时间。上述数据不包含系统剪贴板提供者生成数据、轮询等待或 UI 排版，不能当作
完整复制操作的耗时。小样本、缓存状态和机器负载都会影响结果，搜索变化不作为稳定收益承诺。

复现：

```bash
./tests/performance/clipboard_benchmark.sh baseline
./tests/performance/clipboard_benchmark.sh current
```

## 产品行为

- 普通历史使用持久化 `last_used_at` 做 LRU，保留 200 条；固定记录及最近一次删除批次保留原有保护。
- 成功复制、粘贴或成功写入剪贴板的降级投递更新使用时间。失败、取消、被新剪贴板覆盖、浏览预览不计入。
- 采集时间与使用时间分开，历史复用不让列表跳动。升级迁移不主动淘汰旧记录，不改日期、置顶和删除状态。
- 图片规范化、RTF 解析、哈希和文件读取放到后台。PNG 原始编码直接保存，其余图片仍由系统转换成 PNG。
- 采集最多一个快照在途，涵盖存储写入；完成后读取最新剪贴板，避免慢转码期间累积大量图片缓冲区。
- 异步复制期间检查剪贴板所有权与取消状态；面板关闭时停止数据库刷新，打开时重新读取。
- 去重使用内容哈希索引并校验原文字串，列表和淘汰查询增加适用索引。

## Rust 评估

**本版采用 Swift + ImageIO + CryptoKit + SQLite。** 实测的主要开销是重复图片编码和
主线程工作安排。消除重复计算并调整执行位置，已解决这两个热点。

SQLite 本身是 [C 实现的嵌入式数据库](https://www.sqlite.org/whyc.html)，当前 Swift 代码
直接调用其 C 接口。改为 Rust 包装不会自动减少这部分查询工作。当前 200 条搜索耗时约
1–2 ms，没有发现值得为此增加跨语言边界的计算热点。

Rust 可作为后续跨平台的历史存储、批量文本处理或独立索引模块候选。接入可使用
[C ABI / FFI](https://doc.rust-lang.org/nomicon/ffi.html)，需同时处理数据所有权、错误边界、
arm64/x86_64 构建与打包，并用相同输入比较耗时、内存和整条调用路径。
此轮没有实现 Rust 对照版本，结论是当前缺少引入它的性能依据，不是语言速度排名。

## 验证与边界

核心测试覆盖 LRU 淘汰、旧数据迁移、置顶保护、撤销和失败回滚。专项测试覆盖 PNG/JPEG/文件/RTF、
后台采集顺序、取消、敏感类型过滤、异步复制竞争、投递和隐藏面板刷新。

交付验证：Release 构建、69 项核心测试、剪贴板三组专项和助手回归通过；本机签名与运行环境
检查通过。安装后的 SQLite 完整性检查为 `ok`，迁移前后历史 ID、时间、固定状态、删除状态和
内容哈希一致，全部记录已初始化使用时间。原生快捷面板打开、加载与 Esc 关闭已检查。

容量仍以普通记录数量限制，未新增按字节数自动删除历史的策略。图片缩略图缓存仍使用
100 项 / 32 MiB 的 NSCache 软限制；它与历史记录 LRU 是两层不同的机制。
系统剪贴板快照仍需通过 AppKit 获取，外部应用的数据生成时间不受本次优化控制。

## 0.3.2：不限条数，按空间执行 LRU

普通历史默认使用 1 GiB 的估算内容空间。`storage_bytes` 记录 UTF-8 正文、选中上下文、
已保存图片字节数，外加每条 256 字节预留；固定与可撤销记录另计。它不是整个 SQLite
文件的硬限制。升级只补全统计，不在启动时删除历史。单条内容超出预算时跳过采集并显示
提示，保留已有记录与系统剪贴板。超过预算的旧固定内容取消固定时仍会保留固定状态，
避免记录立刻淘汰。

超过空间预算后，按 `last_used_at` 顺序选择普通记录，在事务中删除；提交成功后才删除
应用自己的图片文件。事务失败会回滚并保留文件。普通历史条数不再参与淘汰条件。

两个界面按 100 条分页加载；搜索与分类先作用于整个数据库，再取当前页。新搜索使在途
旧页面失效，实时采集会合并刷新，避免短时间重复查询。空间统计使用覆盖索引，分页使用
匹配显示顺序的索引，避免统计索引导致首屏排序扫描整段历史。

同机 Swift `-O`，5,000 条生成的中英文文本，估算总大小 13,833,890 字节，每项 30 次：

| 存储层操作 | 中位数 | P95 |
| --- | --- | --- |
| 首屏 101 条（含下一页探测）与统计 | 0.628 ms | 0.697 ms |
| 偏移 4,000 条的页面 | 4.949 ms | 5.196 ms |
| 搜索最旧的一条文本 | 14.829 ms | 15.029 ms |
| 常见关键词搜索首屏 | 0.271 ms | 0.313 ms |
| 新增记录，含后台写入与容量检查 | 0.715 ms | 1.358 ms |

复现：`./tests/performance/clipboard_benchmark.sh history`。这是小型合成数据集的存储层
耗时，不包含 UI 排版、剪贴板轮询或外部程序生成内容，也不代表 1 GiB 历史的搜索上限。
稀有关键词仍需扫描内容，深页 OFFSET 成本会随偏移增加；应依据更大真实负载的测量再引入
全文索引或游标分页。

交付：75 项核心测试、三组剪贴板专项、Release 通用二进制与签名检查通过。隔离原生 UI
用 246 条记录验证主窗口 100 → 200 → 246 条加载，快捷面板 100 → 200 条加载。
安装 0.3.2（build 6）后确认原有 202 条记录的 ID、日期、固定/删除状态、内容哈希与
使用时间不变，17 个图片文件内容一致，SQLite `quick_check` 为 `ok`，运行环境检查通过。
